# R1 working-source backup — 2026-10-26

This checkpoint preserves the current working source, tests and documentation
on `codex/safety-control-refactor`. It includes the earlier control-safety
refactor, cell and FAS telemetry, landscape display/touch changes, headless
recovery and USB diagnostics, and the existing iOS companion prototype.
Publishing this checkpoint does not upload firmware or change live settings.

## Hardware and bench settings

- Active transmitter: Seeed XIAO ESP32-S3, Waveshare RPi LCD (F), schematic (5).
- Approved hardware environment: `seeed_xiao_esp32s3-pcb`, landscape 480×320.
  Portrait and legacy source/build coverage is retained; upload guards reject it.
- `STARTUP_IGNORE_HELD_INPUTS` remains enabled for the XIAO bench trial, as
  requested earlier. Held switch/trim positions do not block startup; mapped
  input faults, neutral/link checks and explicit arming still apply. Restore
  the normal held-input check after the input repairs are complete.
- The LCD runs at the existing 80 MHz trial setting. The LCD-only diagnostic
  source is retained but is not an approved upload target.
- Headless recovery persists separately in NVS and inhibits normal arming.
  Saving HEADLESS OFF requires reboot before local hardware resumes.

## Receiver source

Receiver production code lives in
[ExpressLRS-SPort, codex/sport-telemetry](https://github.com/cmlpreston/ExpressLRS-SPort/tree/codex/sport-telemetry),
commit `7213ac5f6cff7573554942b079a810c1c66c977e` at this checkpoint. Both ER4
and ER6G drivers, tests and guarded upload workflows are present. The ER6G
trial uses fitted CH5/GPIO2 for one-wire S.Port; CH6 is restored to PWM.
The R1 parser accepts 1–12S groups; the current receiver cell trial forwards 4S.
FAS voltage/current are separate from receiver supply. Above-range current
captures are retained and flagged for comparison; calibration is not established.
GPS forwarding is not selected in the receiver trial.

## Backup scope

Git contains source, not the live NVS contents, calibration/model settings,
private WiFi defaults or compiled firmware images. Receiver firmware with
embedded WiFi credentials stays local. Build products, simulator state,
Xcode user data and local caches remain ignored.

The last handset upload preceded this checkpoint, so its displayed Git identity
still names the earlier base commit; a source backup does not update that identity.
Later documentation corrections are included here. No hardware was flashed
while making this backup.

## Validation

- `make -C test run`: native C++, Python workflow and browser tests.
- `.venv/bin/pio run -e seeed_xiao_esp32s3-pcb`: landscape hardware compilation.
- `make -C simulator -j6 audit`: actual LVGL UI audit in both orientations.
- `swift test --package-path ios`: companion protocol tests with mocked responses.
- iOS simulator compilation with signing disabled.

These checks do not establish RF timing, physical display/touch behaviour,
current calibration, or iPhone-to-handset operation. Existing hardware trials
and the receiver project remain the sources for those observations.
