## Generation prompt

One independent generation per vehicle, using this prompt with the subject
substituted:

> Use case: product-mockup. Asset type: transparent RC transmitter model-selection icon. Subject: one generic unbranded electric radio-controlled [SUBJECT]. Detailed clean 3D product illustration, slightly elevated front three-quarter view, entire vehicle visible, centered with 10% clear margin. Recognizable silhouette at 160 pixels wide, tasteful bright body paint, dark rubber tires with readable highlights on both dark and light UI backgrounds. Truly transparent alpha background, no ground, no backdrop, no text, no logos, no watermark, no other objects. Single vehicle only.

Subjects:
- buggy with narrow body, exposed suspension, knobby wheels and rear wing
- truggy with a wide low body, big off-road wheels and rear wing
- short-course racing pickup truck with enclosed fenders
- monster truck with enormous tires and high suspension
- rock crawler with rugged SUV body and articulated suspension
- touring race car with low sedan body, smooth tires and rear spoiler
- F1-style formula racing car, low open-wheel single-seater, exposed slick tires, front wing and rear wing

## Storage design

Persist the image library and per-model selection in flash. PSRAM is volatile:
use it for the active decoded image if required, not as permanent storage.
The firmware includes only RGB565+alpha display exports in flash, not the large
originals. One lazily allocated 115,200-byte PSRAM buffer holds the active tint;
allocation failure falls back to the original image. Recolouring happens only
when the image or colour changes, not every frame.

## Selection and colour

LCD: Setup → Model → Models → Appearance. Cycle vehicle with arrows and colour
with the colour button; changes save to the active model. Original restores the
source paint. Web: Current model → Model image / Body colour → Save appearance.
The web picker supports arbitrary RGB colours; the LCD offers presets.

`include/model_appearance.h` defines per-image body polygons combined with a
chroma mask. Neutral rubber and highlights remain unchanged; wings and coloured
wheel rims are excluded by the spatial masks. These are stylised body/accent
recolours, not semantic material segmentation: some accent panels remain in their
original colour. Refine the polygons if replacing the source artwork.

Model image IDs and RGB colours are stored separately from channel settings in
`jr-r1-models` using `images-v1` and `colours-v1`. Legacy model 1 retains Hyper 7;
other existing slots retain the generic placeholder until an image is selected.
Web changes require an authenticated, writable CUT session; saving appearance
redraws the current page and does not unlock the boot PIN. Flashed to the XIAO via Pi USB on 2026-09-21 after local build and tests.

## Three-colour revision

Primary, accent and base paint now have independent Original/preset/custom
selections, persisted per model. Existing primary selections migrate unchanged;
accent/base default to Original. Painted wings are included. Protected cockpit
regions and mechanical areas retain their source pixels. The masks are authored
for these assets; do not reuse them with replacement photos without review.
`three-colour-preview.png` shows original, primary-only red, accent-only green
and base-only light grey, rendered using the firmware pixel code. It remains a
stylised livery recolour, not a full material reconstruction.

This revision was built/tested locally and flashed via Pi USB on 2026-09-21.
